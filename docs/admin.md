# Админка Sweet Sushi

Собственная панель проекта: без Webflow, GitHub-аккаунтов работников и плагинов. Рабочий режим использует сервер Node.js. На одном GitHub Pages доступен только демонстрационный редактор: он сохраняет правки в браузере и ничего не публикует.

## Проверить на этом компьютере

Из папки `github-project` выполните:

```sh
node scripts/setup-admin.cjs
node scripts/server.cjs
```

Адрес: http://127.0.0.1:8766/admin/ . Логин `admin`; случайный пароль находится в соседнем файле `../.sweet-sushi-private/Доступ к админке.txt`. Повторная настройка без `--reset` не меняет пароль. Эту соседнюю папку нельзя загружать в GitHub.

1. Войдите и найдите блюдо по названию или категории.
2. Измените название, описание, цену, категорию, наличие или фото. У напитков доступны отдельные объёмы и цены; у остальных блюд одна цена.
3. Нажмите «Сохранить черновик»: изменения станут общими для работников, но ещё не видны посетителям.
4. Проверьте «Предпросмотр», затем нажмите «Опубликовать».
5. В режиме GitHub дождитесь завершения публикации Pages и обновите публичный сайт. В локальном режиме создаётся самостоятельная копия сайта в личной папке outbox; настоящий GitHub не изменяется.

Новые блюда добавляются в существующие категории. Переключатель наличия скрывает блюдо, сохраняя его для возвращения. Фото JPG/PNG/WebP/AVIF до 12 МБ панель уменьшает до 1200 px и преобразует в WebP. Исходный файл не меняется. Фото карточек загружаются отложенно. Бургер на первом экране не менялся.

«Обновить черновик» получает последние сохранения сотрудников. Устаревшее сохранение сервер отклоняет: скачайте свою копию, обновите черновик и перенесите нужные правки. Несохранённые правки остаются в памяти вкладки при истечении входа; после повторного входа можно продолжить. Закрытие вкладки теряет несохранённые данные.

## История и копии

В «Истории» хранятся 10 предыдущих публикаций. Возврат версии изменяет только черновик; для показа посетителям нужна отдельная публикация.

«Скачать копию» сохраняет JSON с фото. Импорт копии до 30 МБ заменяет общий черновик после подтверждения, но не публикует его. Для большого архива и полного восстановления копируйте всю папку данных сервера: `menu.json`, `auth.json`, `media/`. Храните её отдельно от публичного кода. Автоматическая внешняя резервная копия пока не настроена.

## Размещение онлайн

GitHub Pages продолжает показывать сайт. Проверку пароля, запись меню и хранение фото выполняет отдельный сервер. Локальный адрес работает только пока запущен этот компьютер; работникам нужна постоянная HTTPS-ссылка.

Подойдёт управляемый хостинг Node.js с постоянным диском, либо размещение всего сайта на таком хостинге. Арендовать и администрировать VPS необязательно. Учётная запись хостинга, его тариф и постоянное хранилище ещё не выбраны. Бесплатное размещение здесь не обещается.

Настройки сервиса:

- Node.js 24; зависимостей нет. Команда запуска: `npm run start:production`.
- `HOST=0.0.0.0`, `PORT` задаёт хостинг.
- `MENU_DATA_DIR` — абсолютный путь на постоянном диске, например `/data`. Один процесс сервера, одна общая папка данных.
- `ADMIN_PASSWORD` — секрет хостинга, минимум 12 символов. Нужен для первого запуска. `ADMIN_USERNAME` необязателен, по умолчанию `admin`. После создания `auth.json` этот секрет не заменяет существующий пароль.
- `PUBLIC_SITE_ORIGIN=https://bananjojo.github.io` — origin публичного сайта, без `/burger/`.
- HTTPS обязателен. Прокси должен сохранять публичный заголовок Host; cookie в production имеет Secure. HTTP-просмотр production не позволит оставаться авторизованным.

Подготовлен Dockerfile. Постоянный том подключается к `/data`; пароль задаётся через секреты платформы, не через Dockerfile. Production без настроенного первого пароля отказывается стартовать. `.env.example` — пример: сам сервер `.env` не читает.

## Публикация на GitHub Pages

Сервер работает только для админки. Публичный сайт получает HTML, фото и цены непосредственно с GitHub Pages; отключение админки не мешает последней опубликованной версии. На самом сервере адрес / ведёт в админку.

Механизм публикации и секреты хостинга настраиваются по [инструкции](publishing.md). Раньше проект загружал меню через API; этот режим удалён из публичной страницы. Одной загрузки кода в GitHub недостаточно для подключения кнопки публикации: нужен серверный ключ выбранного репозитория.

## Доступ

Пароль проверяет сервер по хешу scrypt. В публичном JavaScript пароля нет. Сессия в HttpOnly cookie действует 8 часов; выход, перезапуск сервера и замена пароля прекращают сессии. Запись требует токен CSRF и свой Origin. После пяти неверных входов адрес блокируется на 15 минут. За общим обратным прокси лимит может быть общим для сотрудников.

Заменить пароль: `node scripts/setup-admin.cjs --reset` с тем же `MENU_DATA_DIR`. Локально создаётся случайный пароль и обновляется личный файл доступа; на хостинге можно передать новый `ADMIN_PASSWORD` через секрет окружения этой команды. Файл доступа можно удалить после переноса пароля в менеджер паролей: для входа он не нужен.

В первой версии один общий аккаунт команды. Отдельные роли и персональные аккаунты работников не реализованы; история показывает общий логин. Заказы и оплата по-прежнему согласуются через WhatsApp; учёт заказов в админку не входит.

## Проверки

`npm test` проверяет корзину, меню, вход/выход/срок сессии/смену пароля, блокировку попыток, защиту записи, конфликт правок, фото, копию, публикацию, историю, восстановление и перезапуск. `npm run build` и `npm run check` проверяют статическую сборку.

Новый интерфейс входа и мобильный вид в браузере в этой сессии не проверены: доступ автоматизации к локальному origin был отозван ранее. Онлайн-размещение не выполнено.
