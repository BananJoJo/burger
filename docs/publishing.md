# Автономный сайт и сервер только для админки

Согласованная схема: посетители получают HTML, фотографии, стили, корзину и цены с GitHub Pages. Публичная страница не запрашивает API админки. Хостинг Node.js обслуживает вход работников, черновик, обработанные фотографии, историю и отправку публикации в GitHub.

Если сервер админки отключится, продолжит работать последняя версия на Pages. Внести новые правки до восстановления сервера не получится. Сайт по-прежнему зависит от доступности GitHub Pages, а переход в WhatsApp — от доступности WhatsApp. Разделение серверов этих зависимостей не устраняет.

## Что делает «Опубликовать»

1. Админка проверяет сохранённый общий черновик и наличие фотографий.
2. Читает текущую версию `index.html` выбранной ветки GitHub.
3. Заменяет только меню, категории и каталог корзины; сохраняет остальное оформление страницы.
4. Передаёт HTML, источник меню `assets/menu-data.json`, фотографии `assets/media/`, автономный загрузчик `assets/site.js`, стили фото и `.nojekyll` одним коммитом.
5. Обновляет ветку без принудительной перезаписи. Чужие файлы, домен CNAME и изменения вне меню сохраняются. Если ветка успела измениться, публикация отклоняется: нужно повторить её на свежей версии.
6. GitHub Pages собирает и разворачивает полученный коммит. Ответ админки «передано в GitHub» означает отправку, а не подтверждение окончания развёртывания. Посетитель увидит изменения после завершения Pages и обновления страницы.

Неиспользуемые старые фотографии автоматически не удаляются: они могут понадобиться для истории и восстановления. Размер репозитория по мере накопления материалов нужно отслеживать. Пароль админки, серверный ключ, `auth.json` и личные резервные копии в публикацию не входят.

## Однократная настройка владельцем

Репозиторий по умолчанию — `BananJoJo/burger`, ветка `main`. В Settings → Pages должно быть настроено развёртывание из этой ветки, корень `/`. Репозиторий должен уже содержать актуальную папку проекта, загруженную как корень, включая `index.html`, `assets/`, `scripts/`, `admin/`, `server/`. Данная функция отправляет изменения меню, а не первоначальную установку всего проекта.

На сервере задаются переменные:

```text
NODE_ENV=production
MENU_PUBLISH_MODE=github
GITHUB_REPOSITORY=BananJoJo/burger
GITHUB_BRANCH=main
MENU_DATA_DIR=АБСОЛЮТНЫЙ_ПУТЬ_К_ЛИЧНОЙ_ПАПКЕ
```

`MENU_GITHUB_TOKEN` задаётся отдельно в секретах/закрытом окружении хостинга. Владелец создаёт fine-grained personal access token только для этого репозитория с разрешением Contents: read and write. Ключ не вводится в клиентский JavaScript, интерфейс админки, переписку, Dockerfile или репозиторий. Работникам достаточно общего пароля админки; GitHub-аккаунты и этот ключ им не выдаются. Срок действия и ограничения ветки должны позволять публикацию. При истечении ключа сайт продолжит работать, отправка новых публикаций остановится до его замены.

Используется отдельный серверный ключ владельца, не `GITHUB_TOKEN` из GitHub Actions. Последний имеет особенности запуска Pages. Если репозиторий использует собственный workflow, требуется проверить его совместимость отдельно. Текущее подключение рассчитано на Pages из ветки.

На Hostland стартовый файл — `server.js` в каталоге приложения. Подготовлен такой вход; реальная установка ещё не проверена. Требуются Node.js 18+ (предпочтительно 24), HTTPS, постоянная папка данных вне `public/` и один процесс приложения. Одновременные несколько процессов этой файловой версии не поддерживаются. Версию Node, число процессов Passenger, установку секретов и резервное копирование папки данных надо подтвердить в тестовом аккаунте до оплаты.

Админка открывается на отдельном адресе хостинга `/admin/`. Публичному сайту адрес сервера не нужен. `assets/backend-config.js` используется только страницей админки, если нужно сделать переход с её статической копии на сервер; публичный `index.html` его не загружает.

## Локальная проверка без ключа

Обычный запуск `node scripts/server.cjs` по умолчанию использует `MENU_PUBLISH_MODE=local`. Кнопка называется «Собрать тестовую версию» и создаёт полную автономную папку `../.sweet-sushi-private/outbox/ИДЕНТИФИКАТОР/`. Она содержит сайт и фото, без сервера и секретов. Ничего в настоящий GitHub не отправляется. В production по умолчанию используется режим github: без ключа публикация блокируется с понятным сообщением, черновик сохраняется.

После реальной публикации источник `assets/menu-data.json` сохраняет актуальное меню для следующих сборок: `node scripts/build.cjs` не должен возвращать устаревшие цены из `docs/content.md`. На исходном проекте без этого файла применяется прежнее меню из документа. `admin/seed.json` при сборке обновляется из актуального источника, а настройка нового сервера переносит фото из `assets/media/` в его личную папку. Существующий общий черновик сервер не перезаписывает при развёртывании кода.

## Проверки и текущий статус

`node scripts/test-publisher.cjs` проверяет автономный сайт и все локальные ресурсы, корзину с новыми ценами, экранирование, холодные напитки, сохранность исходного оформления, повторную сборку, загрузку фото в имитацию GitHub API, единый коммит, сохранность чужих файлов, конфликт ветки, повтор после потерянного ответа и отказ без ключа/сети. Тесты не отправляют коммиты в реальный репозиторий.

Код подготовлен и проверяется локально. Настоящий ключ, аккаунт Hostland и живая публикация GitHub Pages в этой сессии не подключены. Визуальная проверка новой панели в браузере остаётся отдельным шагом: доступ автоматизации к локальному origin ранее был отозван.
